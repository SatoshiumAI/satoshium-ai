# The Satoshium Manifesto

**Directory:** `/manifesto/`  
**Public page:** `index.html`  
**Primary Markdown companion:** `manifesto.md`  
**Status:** Active foundational Satoshium document

## Purpose

The `/manifesto/` directory contains **The Satoshium Manifesto — A Calm Build for a Verifiable Future**.

The Manifesto is a foundational Satoshium document expressing the project’s guiding ideas, long-term orientation, relationship to Bitcoin, commitment to verifiability and transparency, and approach to building in public.

This README documents the repository role of the directory. It does not replace the Manifesto itself.

## Directory Structure

```text
/manifesto/
├── index.html
├── manifesto.md
└── README.md
```

## Public and Repository Representations

`index.html` is the primary public-facing presentation of the Manifesto.

`manifesto.md` is the repository-readable Markdown representation of the Manifesto text.

`README.md` documents the directory, the relationship between those two representations, and maintenance expectations.

The Manifesto should remain readable as a substantive document in its own right rather than being converted into repository documentation.

## Foundational Role

The Manifesto currently presents Satoshium as a long-term exploration of intelligence operating within verifiable systems and transparent rules.

Its recurring themes include:

- verifiability over opaque authority;
- transparent and inspectable systems;
- Bitcoin as infrastructure rather than ideology;
- clearly defined boundaries for intelligent systems;
- modularity and long-term accountability;
- educational infrastructure;
- public research and experimentation;
- open development;
- durability over hype;
- preservation of human agency.

These are expressed as guiding ideas and project orientation rather than as a complete specification of formal Suite institutional architecture.

## Relationship to the Satoshium Suite

The Manifesto predates and conceptually supports later Satoshium architecture, but it should not be treated as redefining the current formal responsibilities of Atlas, Navigator, Certifier, Registry, Chronicle, Anchor, Beacon, or Attestor.

Where Manifesto language is broad, aspirational, or foundational, later institutional documentation may provide more precise operational definitions.

The Manifesto therefore serves as a foundational statement of direction, not as a substitute for current canonical institutional documentation.

## Bitcoin Alignment

The Manifesto explicitly describes Bitcoin as a natural base layer for systems requiring verifiable ownership, transparent rules, global accessibility, resistance to coercion, and reduced dependence on centralized institutional trust.

Its stated relationship is:

> Satoshium aligns with Bitcoin not as ideology, but as infrastructure.

This framing is part of the Manifesto’s foundational orientation and should be preserved when reconciling repository documentation.

## Built in Public

The Manifesto identifies open development as a deliberate design choice intended to make progress visible, ideas examinable, systems understandable, and future participation possible.

This repository directory is one expression of that principle: the public HTML presentation and Markdown source remain inspectable alongside one another.

## Source-of-Truth Discipline

For this directory:

- `index.html` is the current public representation;
- `manifesto.md` is the Markdown representation of the Manifesto;
- `README.md` documents the directory and should not duplicate the full Manifesto text;
- substantive changes to the Manifesto should be reflected consistently across both `index.html` and `manifesto.md`.

Where the HTML and Markdown versions differ, the discrepancy should be reviewed deliberately rather than silently resolved through README maintenance.

## Authority Boundary

The Manifesto is foundational and interpretive. It does not by itself transfer authority among Satoshium institutions, records, or operational surfaces.

Later formal Suite architecture remains authoritative for institutional responsibilities and canonical objects.

**REFERENCE DOES NOT TRANSFER AUTHORITY.**

## Maintenance

Repository maintenance for `/manifesto/` should:

- preserve the Manifesto as a distinct foundational document;
- keep `index.html` and `manifesto.md` substantively synchronized;
- avoid rewriting historical or foundational language merely to match later institutional terminology;
- distinguish broad project principles from formal Suite architecture;
- record and resolve textual divergences deliberately;
- use `README.md` for repository documentation rather than replacing the Manifesto with README-style prose.

README reconciliation documents the architecture and repository state that exist. It does not redesign them.
