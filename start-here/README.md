# Satoshium Start Here

**Directory:** `/start-here/`  
**Public entry page:** `index.html`  
**Markdown companions:** `start-here.md`, `origins.md`  
**Additional public page:** `origins.html`  
**Status:** Active public orientation and onboarding section

## Purpose

The `/start-here/` directory serves as the primary orientation point for new visitors to Satoshium.

Its public `index.html` introduces the project at a high level, provides a visual and video overview, links to onboarding and origin materials, and directs visitors toward architecture, systems, updates, Aegis, simulations, and the broader Satoshium domain ecosystem.

This README documents the repository role of the directory. It does not replace the substantive orientation or origin documents.

## Current Directory Structure

```text
/start-here/
├── index.html
├── start-here.md
├── origins.html
├── origins.md
└── README.md
```

Additional subdirectories or onboarding surfaces may exist beneath `/start-here/`, including the current Onboarding Mentor destination.

## Public Entry Page

`index.html` is the primary public representation of the Start Here section.

It currently includes:

- a general introduction to Satoshium;
- embedded video and visual overview material;
- a high-level description of what Satoshium is;
- an Onboarding Mentor entry point;
- an origin-story link;
- suggested navigation through the platform;
- descriptions of Aegis and Chess Signal;
- a suggested visitor path;
- build philosophy;
- a cross-domain ecosystem overview.

The page functions as an orientation surface rather than as a formal Suite institutional document.

## Markdown Companion: `start-here.md`

`start-here.md` is a repository-readable orientation document.

It presents an earlier or simplified articulation of:

- Satoshium’s purpose;
- domain roles;
- project origins;
- suggested platform progression;
- build philosophy;
- an older five-layer architecture model:

`Trust → Knowledge → Intelligence → Signal → Simulation`

Because some of that terminology predates later Satoshium institutional architecture, `start-here.md` should not automatically be treated as the current canonical description of Suite structure where it differs from current formal documentation.

## Origin Materials

`origins.html` and `origins.md` document the origin narrative of Satoshium.

They describe the conceptual synthesis of:

- Bitcoin as a system of verifiable rules and value coordination;
- AI as a capability multiplier for individual builders;
- Satoshium as an exploration of how Bitcoin-style verifiability might inform intelligence infrastructure.

These origin materials are narrative and historical. They should remain distinct from the repository README and from later formal institutional architecture.

## Onboarding Role

The Start Here section provides orientation rather than authority.

It may point visitors toward:

- Onboarding Mentor;
- Architecture;
- Systems;
- Updates;
- Progress surfaces;
- Aegis;
- simulations and games;
- domain-specific Satoshium surfaces.

Those references help visitors navigate the ecosystem but do not transfer the authority or canonical responsibility of the destination into `/start-here/`.

**REFERENCE DOES NOT TRANSFER AUTHORITY.**

Likewise:

- **Connection ≠ Identity.**
- **Reference ≠ Derivation.**
- **Reference ≠ Support.**
- **Reference ≠ Authority Transfer.**

## Relationship to the Satoshium Suite

The Start Here section is not a formal Suite institution.

Its purpose is explanatory and navigational.

Current formal responsibilities of Atlas, Navigator, Certifier, Registry, Chronicle, Anchor, Beacon, and Attestor remain defined by their own institutional documentation and should not be inferred from broad onboarding descriptions on this page.

Where the Start Here materials contain earlier architectural language, those statements should be treated as orientation or historical context unless later reconciled into current institutional terminology.

## Source-of-Truth Discipline

For repository maintenance:

- `index.html` is the principal public orientation page;
- `start-here.md` is a Markdown orientation companion but may contain older architectural framing;
- `origins.html` is the public origin-story page;
- `origins.md` is the Markdown origin-story companion;
- `README.md` documents the directory and the relationship among these files.

The README should not duplicate the full contents of the orientation or origin documents.

## Maintenance

Repository maintenance for `/start-here/` should:

- keep public navigation links current;
- preserve the distinction between orientation content and formal institutional architecture;
- keep `origins.html` and `origins.md` substantively synchronized;
- review `start-here.md` when older architectural terminology becomes materially misleading;
- avoid silently rewriting historical origin material to fit later architecture;
- preserve onboarding clarity without turning this directory into an authority-bearing layer;
- flag stale architectural descriptions for deliberate later reconciliation rather than fixing them opportunistically.

README reconciliation documents the orientation structure that exists. It does not redesign it.
